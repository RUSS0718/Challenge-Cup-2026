# ARM-Harness v1 详细实现文档

> Repository: `RUSS0718/Challenge-Cup-2026`
> Base branch: `codex/repo-hygiene-cleanup`
> Development branch: `feat/arm-harness-v1`

# 1. 实现原则

本轮只做 ARM-Harness 最小闭环：

```text
per-call thinking control
        ↓
ReasoningModePolicy
        ↓
lane-specific budget
        ↓
OFF-first conditional escalation
        ↓
telemetry
        ↓
paired experiment
```

不同时修改：

```text
FSDF prompt
Candidate Parser
Skill
RAG
Answer Bank
Verifier algorithm
Official submission config
```

尽量保证实验可归因。

# 4. 第一步：修改 llm_client.py

## 4.1 当前问题

现在：

```python
class InternChatClient:
    def __init__(
        ...,
        thinking_mode: bool | None = None,
    ):
        self.thinking_mode = ...
```

随后：

```python
chat(...)
```

使用：

```python
self.thinking_mode
```

这意味着 Thinking 是 Client 级别状态。

```text
Call 1 = OFF
Call 2 = ON
Call 3 = OFF
```

# 5. 引入 request-local reasoning mode

建议首先定义：

```python
from typing import Literal

ReasoningMode = Literal["inherit", "off", "on"]
```

增加：

```python
def _resolve_reasoning_mode(
    self,
    reasoning_mode: ReasoningMode,
) -> bool | None:
    if reasoning_mode == "off":
        return False
    if reasoning_mode == "on":
        return True
    return self.thinking_mode
```

修改：

```python
def chat(
    self,
    messages,
    temperature=0.2,
    max_tokens=4096,
    *,
    reasoning_mode: ReasoningMode = "inherit",
) -> str:
```

计算：

```python
effective_thinking_mode = self._resolve_reasoning_mode(
    reasoning_mode
)
```

然后：

```python
if effective_thinking_mode is not None:
    payload["thinking_mode"] = effective_thinking_mode
```

不要：

```python
self.thinking_mode = ...
```

# 13. ReasoningModePolicy v1

输入直接复用：

```python
ProblemContract
```

不要新写第二套 classifier。

逻辑建议：

```python
class ReasoningModePolicy:

    def __init__(
        self,
        *,
        allow_thinking_on: bool,
    ):
        self.allow_thinking_on = allow_thinking_on
```

核心：

```python
def plan(self, contract, answer_type) -> SolvePolicy:
```

规则：

```text
direct
+ high confidence
+ scalar / choice
    ↓
FAST_OFF

otherwise
    ↓
ADAPTIVE
```

当：

```text
allow_thinking_on=False
```

ADAPTIVE 的 fallback 仍然是 OFF。

即：

```text
OFF
→ OFF recovery
```

当：

```text
allow_thinking_on=True
```

才允许：

```text
OFF
→ ON escalation
```

# 19. 建议重构顺序

原代码：

```python
self.ledger = EvidenceLedger()

    max_calls=self.config.effective_call_limit,
    total_tokens=self.config.token_limit,
```

```python
self.ledger = EvidenceLedger()

    total_tokens=solve_policy.token_budget,
```

```text

```

---

# 29. OFF → ON 不做 continuation

原则上：

```text
OFF 失败
→ ON independent solve
```

而不是：

```text
OFF unfinished reasoning
→ ON continuation
```

这样能保持候选独立性，也更容易分析：

```text
OFF candidate
vs
ON candidate
```

# 31. Candidate conflict

如果 OFF 已得到 Candidate A，ON 得到 Candidate B：

```text
A != B
```

不要立即再调用一个 Full Solver。

执行：

```text
normalize
→ answer_equivalence
→ deterministic check
```

仍冲突时：

```text
bounded critic
```

Critic 推荐：

```text
reasoning_mode=off
```

因为它只负责比较既有 Candidate。

# 36. Profile 语义

### arm-off

```text
ARM enabled
Thinking ON disabled
所有 Solver Call 强制 OFF
```

### arm-on

```text
实验专用
Solver 强制 ON
```

用于建立 explicit ON baseline。

### arm-static

```text
Static Policy
direct → OFF
high-risk → ON
```

只有 explicit ON health gate 通过之后跑。

### arm-adaptive

```text
OFF primary
→ conditional ON
```

最终候选方案。


```bash
git revert <promotion_commit_sha>
```

不要为了 rollback 删除整个 ARM 代码。

实验能力保留，submission 开关关闭即可。
