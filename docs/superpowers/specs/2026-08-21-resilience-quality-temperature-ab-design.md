# 可用性、正确率与温度单变量实验设计

日期：2026-08-21  
状态：已获用户口头认可，待审阅本文后实施

## 背景与问题边界

默认提交路径是 F+4096、最多两次 `client.chat` 调用。近期公共 112 集的 F+4096 基线
Correct 分别为 83、86、88、83；Invalid 分别为 4、1、2、1。单轮 Correct 的自然波动
至少达到 5，故单次 +1 不能视为提升。

答案前置、严格 salvage、6144 条件重试、低温重试、极短恢复 Prompt、长题 token 路由、
RAG 与确定性求解器默认启用均已拒绝。本轮不重新测试这些方向，不按题号、题面或样例答案
路由，也不使用 client 私有字段。

## 成功标准

- 保持公开接口 `client.chat(messages, temperature, max_tokens)`；默认配置完全不变。
- 每题最多两次模型调用，平均调用不超过 1.5，非空输出率 100%。
- 所有候选先在公共 112 集与同批 F+4096 对照各跑两轮；只有通过预注册 gate 的候选再在
  复杂冻结 48 集跑两轮。
- Correct 路线：两轮均不低于同批基线，平均至少多 2 Correct，Invalid/Incorrect 不升。
- 可用性路线：两轮平均至少少 2 Invalid，Correct 不降，Incorrect 不升。
- 温度路线：两轮均不低于同批基线，平均至少多 2 Correct，Invalid/Incorrect 不升。
- 没有达到上述门槛即记录拒绝，不提交官方 canary，也不改变默认路径。

## 0. 基线方差校准

先额外运行四轮 F+4096（R3–R6），记录 Correct、Invalid、模型错误率、平均/P95 延迟与调用数。
它不改变代码。报告用六轮总体 min/max、均值、标准差解释后续候选的效果量，避免将 API
服务波动误认为算法收益。

## 1. 可用性：失败后的延迟恢复

仅当首次调用没有产生候选，且 trace 已记录 `model_error` 时，在既有第二次调用前等待固定
1 秒；再以**完全相同**的基线 Prompt、温度和 4096 token 重试。无模型错误、已有候选、
答案格式不合规但没有请求失败的情况不等待，也不改变现有恢复路径。

该变体只改变第二次调用的时序，不需要也不读取具体 client 实现或错误私有字段。它的假设是
部分超时/短暂服务故障会在短暂退避后恢复；若错误不具瞬态特征，结果应与基线相同或更慢，
并会被 gate 拒绝。

## 2. 正确率：显式终答冲突的独立复算

仅当同一模型输出中出现至少两个显式 `最终答案：` / `答案：` 标记，且它们经既有通用
等价判断确认互不等价时，执行一次独立复算。第二次调用仍使用基线 Prompt、温度 0.6 与
4096 token；没有冲突的清晰答案保持一次调用。

这是一个窄的、可形式化的“回答自相矛盾”条件，不按学科或题目内容特判，也不放宽答案
提取。覆盖率可能很低；低覆盖本身不是失败，但若没有达到 Correct gate 就不会晋升。

## 3. 正确率：主调用温度扫描

分别测试主调用及其既有条件重试均为温度 0.4 和 0.8。token、Prompt、解析、最大调用数及
失败恢复均保持基线一致。此前“仅重试用 0.1”的负结果不能推出“主调用 0.4/0.8”无效，
因此将它们作为新的独立单变量。

温度候选先各跑公共集两轮；只有显著优于 0.6 的一个温度进入复杂冻结集双轮。若两者都不
通过，则不再增加温度点，防止对本地集调参。

## 执行顺序与报告

1. 基线 R3–R6；
2. 失败后的延迟恢复（两轮）；
3. 显式终答冲突复算（两轮）；
4. 温度 0.4、0.8（各两轮）；
5. 仅对通过公共 gate 的候选跑复杂冻结两轮；
6. 将每个候选的配置、实际调用上限、Correct/Invalid/Incorrect、平均/P95 成本与 gate
   结论写入安全汇总报告，不保存模型原文。

实现中的实验开关一律 default-off；若所有候选失败，产物仍是可复现实验报告和明确的否决
证据，而不是默认行为变更。
