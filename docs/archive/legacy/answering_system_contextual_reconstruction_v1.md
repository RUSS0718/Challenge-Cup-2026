# Contextual Answer Reconstruction v1

状态：`IMPLEMENTED / DEFAULT_OFF / NOT_VALIDATED`

## 目的

这是一套针对长题输出失效的答题体系，不是新的评分器，也不是把 `UNKNOWN` 改成猜测答案。它解决的是：模型已经写出一部分推理，但没有形成可判的终答帧，或者把提示词中的占位符当成答案。

## 处理流程

```text
原题
  │
  ▼
最多三路异构求解（每路 4096 token，沿用最终答案标记）
  │
  ├─ 出现可证明共识 ──► 直接输出
  │
  └─ 无共识/无答案/冲突/占位符/确定性卫生失败
       │
       ▼
有限候选草稿（每份保留头部 + 尾部）
       │
       ▼
一次上下文重构（默认 4096 token，可独立纠正）
       │
       ├─ 有唯一、可验证的显式答案 ──► 输出
       └─ 否则 ──► 最后一条独立候选或 UNKNOWN
```

## 与已失败方法的区别

- 不使用 V5 的 `ANSWER:` 单一新协议；采用仓库历史基线已经使用过的 `最终答案：` / `Final answer:` 形式，并修正英文 marker 的正则错误。
- 重构请求会看到受限的候选草稿；V5 的第二次请求完全丢弃首轮推理，无法利用已经得到的变量、等式和边界信息。
- 不执行尾段续推；不会把草稿尾部直接当答案，第二次响应必须重新产生显式答案。
- 不使用 KCV 的四行选择协议、GSA 聚合或自由 self-refine；重构器只在候选无共识时触发，失败后保留最后一条独立候选。

## 安全约束

- 复杂题最多 5 次模型调用：最多 3 路候选、1 次重构、1 次独立兜底；已有共识时提前停止。
- 草稿只作为不可信证据，不进入 `final_response`。
- 标记值必须是紧凑数学 token；`<result>`、自然语言句子、拼接英文尾巴和多个冲突答案被拒绝。
- 多个答案无法证明等价时 fail-closed；重构与独立兜底都失败返回 `UNKNOWN`。
- RAG、工具、MCP、沙箱和默认提交配置不参与该方法。

## 适用边界

该方法最可能改善 `invalid → 可判答案` 的迁移，不能保证 `incorrect → correct`。如果在难题上仍没有形成答案，说明瓶颈是底层推理能力或端点行为，不应继续放宽抽取器。

实现入口：`user_agent.py` 中的 `enable_contextual_answer_reconstruction`，默认值为 `False`。
