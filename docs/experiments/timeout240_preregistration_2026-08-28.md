## 超时体制变更(90s → 240s)

**依据**(战斗之夜解剖,`battle_night_2026-08-28_results.md`):
复杂题单调用生成时长天然贴着 90 秒边界(均值 ~4800 token/调用,思考主导),
端点拥塞时吞吐下降即大量越界——这是 6 连 VOID 的唯一根因;
官方侧单题预算 20 分钟、runner error=0,证明生成本身可完成。
**旧窗全部 VOID,可比性沉没成本为零**,故 240s 新体制不构成协议污染。
适用范围:仅本地实验 runner 参数(--timeout-seconds 240),
不触碰 agent 配置、提交配置与官方路径。

**void 门维持**:任一臂 model_error 率 >10% 整窗作废——240s 下预期错误率
塌缩至健康位(~2-5%);若仍越门,说明端点已病到测量不可信,门继续履职。

**dev3 探针降级为参考项**:已证明无法预测长窗健康度,不再作为启动前置;
窗口级 void 门是唯一健康判据。
