## Run #4：C0 answer_first+k5（commit `b8b78aa`,提交仓库 main）

- **评测窗口**：2026-08-26T23:29:02Z 进入 agent stage,04:41:17Z 完成,约 5 小时 12 分。
- **锚点说明**:`b8b78aa` 是 gitcode 提交仓库 main 的 tip(08-26 12:58 推送),
  SUBMISSION_CONFIG = answer-first prompt + k5 自适应投票 + 4096;**本地 main
  (`e4b40c0`,canary gated profile)与它已分叉**,引用"main 配置"必须注明指哪个。

### 分析

1. **四代配置收敛于 9**:k5 变体(旧默认/R2)→32k/k5(R2)→B1 门控(R3)→
   C0 answer-first+k5(R4),correct 全部为 9~11。配置层的可挖增量已经见底;
   本地门测的 +23% 收益没有迁移到隐藏集。
2. **answer-first 的真实作用是"带伤可判"而非提分**:截断率回到 88.7%
   (与 R1/R3 一致),但 invalid 从 R3 的 37 降到 20——被截断的输出里,
   答案前置让更多仍可解析。incorrect 相应膨胀到 83。
3. **20 个 invalid 是当前唯一确定的免费分数池**:P1 invalid 缩减包
   (空响应兜底、答案行强制化、规范归一)的官方期望收益为 +0~1~2,
   且机制通用、无过拟合风险(ADR 口径:规则须对任意输入成立)。
4. **耗时教训持续有效**:5h12m 逼近 6h 红线的一半以上;k5×88.7% 截断
   的调用结构在慢窗口下有触顶风险,任何新配置不得比 C0 更重。

## Run #2：32k + k5 投票（commit `b082c36`）

- **评测窗口**：2026-08-23T19:20:09Z 进入 agent stage，2026-08-24T04:43:12Z 完成，
  求解约 9 小时 23 分钟。注意：AGENTS.md 记载整轮上限 6 小时，本轮实际超出且未被罚
  （deadline_seconds=0），属于平台宽容，不可依赖。

### 判分结果

| 指标 | 值 |
|------|----|
| total / graded / skipped | 112 / 112 / 0 |
| correct / incorrect / invalid | 9 / 43 / 60 |
| accuracy | **8.04%（9/112，与 Run #3 完全相同）** |
| valid_accuracy | 17.3%（9/52） |
| run_summary success / error | **58 / 54**（过半题目 agent 阶段报错） |
| degraded / infra_error_count | false / 0（judge 侧无基础设施故障标记） |

### 用量

| 指标 | 值 |
|------|----|
| request_count / attempt_count / retry_count | 379 / 454 / **75** |
| truncated_count | 214（47.1%，32k 上限下仍然存在） |
| completion_tokens | 2,075,063（约 4,570/尝试） |
| total_tokens | 2,132,258 |

### 分析

1. **与 Run #3 同分（9/112）**：同一隐藏集上，"提额到 32k + k5 多采样投票"和
   "B1 门控 + 4k"拿到完全相同的 correct 数。配置层差异（上限高低、投票还是门控）
   目前不改变正确数——瓶颈在两者共同的下游。
2. **但答案质量结构不同**：invalid 60 vs 37、valid_accuracy 17.3% vs 12.0%。
   提额的主要收益是把部分截断垃圾从"无法解析"变成"可解析但错误"
   （invalid→incorrect 迁移），并没有转化为正确数。
3. **runner 层 54 题 error + 客户端 75 次重试**：该窗口服务不稳定且长尾极重；
   9h23m 的墙钟时间意味着 k5×32k 在慢窗口下单题极易触顶。60 个 invalid 中
   相当比例可能来自这 54 个报错题的兜底输出。
4. **32k ≠ 无截断**：47% 的尝试仍出现截断。要么 k5 投票路径的单采样实际预算
   远小于 32768，要么隐藏集推理长度分布极端。在拿到逐请求 finish_reason 之前，
   不能把 32k 理解为"截断问题已解决"。
5. **成本与风险**：total tokens 是 Run #3 的 3.2 倍、墙钟 7.4 倍、且有 54 题 error。
   同分条件下，本配置在鲁棒性与成本上全面处于劣势。

## 跨轮结论与行动项

1. **两套配置同分 8.04%（Run #2/#3 同题集配对）**：token 上限、投票/门控之争
   不是当前主要矛盾；真正的瓶颈是约 92% 未解题上的核心推理能力与分布落差
   （本地 112 集历史 ~81% vs 隐藏集 8%，AGENTS.md 反过拟合条款持续有效）。
2. **同分比代价，B1+4k 当前占优**：零 infra 错误、1.3h、669K tokens，对比
   32k+k5 的 54 题 error、9.4h、2.13M tokens。在没有更高分的第三配置之前，
   维持 `9497118`（B1+4k）为基线投稿比机械回滚 `b082c36` 更符合证据——
   此前"回退线"的预设已被本轮数据推翻，是否切换由团队确认后更新此处。
3. **截断的两面性**：4k 上限 ≈ 88% 截断（稳定复现）；提额到 32k 后仍有 47% 尝试
   截断，且收益仅停留在 invalid→incorrect 迁移（valid_acc 12%→17.3%）。
   `gated_retry_8k` 臂（issue #13 复测协议主臂）要回答的问题因此收窄为：
   "提额+门控能否把更高的 valid_accuracy 转化为 correct 增量"。
4. **后续所有配置决策必须同时看五个数**：accuracy、valid_accuracy、invalid 数、
   截断率、runner error 数；单看 accuracy 会把基础设施伤害误读成能力不足，反之亦然。
