# 实验 C 报告：非数值题型标记抽取（双轮 A/B）

日期：2026-08-14
分支：`experiment/thinking-suppression`（main 未动）
改动：**仅**实现严格、有边界的标记抽取 `extract_answer_segment`，并把非数值题型
（derivation/proof/explanation）的判分 `answer` 从「完整响应」改为「答案段」
（抽取失败则 fallback 完整响应，不丢弃证明/解释题）。`final_response` 仍保留完整
解答（未动 `_format_task_final_response`）。token=3072、temperature=0.6、重试、开关不变。

## 1. 抽取器契约（14 项边界单测，全通过）

`extract_answer_segment(response)`：
- 取**首个**「最终答案/final answer/答案」标记后的段，到下一个结构标题
  （推导/证明/解释/最终答案）或空行为止；
- **跳过** thinking 复述的占位符回显（`<…>` 或 prompt 复述词）；
- 原样返回，**不做数值规范化**（不等式/集合/有序元组/自然语言结论保持原语义）。
- 边界单测覆盖：单行数值/表达式、多行结论、后接完整证明、无标记、截断、重复标记、
  不等式、集合、有序元组、自然语言结论、条件不足、thinking 占位符回显。

## 4. 关键发现

1. **抽取器改动正确、有效**：derivation 从 0% 直接跃升到 **80%**（16/20 正确、
   0 错误、4 unknown）——证明「完整响应 → 答案段」这一步是决定性收益来源，且
   `incorrect=0` 依旧成立。

2. **proof/explanation 的瓶颈已从「抽取器」转移到「judge 层」**：它们的
   `extracted_answer` 现在是**正确**的答案段，但格式是「命题成立；…=X」或完整
   解释句，本地 `judge_correct` 无法解析中文结论前缀，故仍判 unknown：

   - 6009 proof：`命题成立；矩阵A的行列式为-1`（期望 -1）→ 语义正确，judge unknown
   - 6040 proof：`命题成立；f(2)=6`（期望 6）→ 语义正确，judge unknown
   - 6017 explanation：`…完全图K_5所有顶点度数之和为20`（期望 20）→ 语义正确，judge unknown

   **这不代表官方会判错**——官方主评分字段是 `final_response`（完整解答，含
   「最终答案」+ 完整证明/解释正文），本地 `extracted_answer` 仅作辅助。本地
   judge 的 unknown 是 judge 自身的表示解析局限。

3. **残留边界（可后续收紧，非本轮目标）**：英文 `Proof:` 标题未被段边界正则识别
   （6010 段尾吞入后续证明）、个别英文 thinking 复述未全过滤（6019）、个别段被
   length 截断（6018）。

## 5. 结论与下一步

- 实验 C 目标达成：**标记抽取单独落地，derivation 0%→80%，且 thinking 泄漏率
  （16.7–18.8%）与 length（25–27%）同步下降**，方向两轮一致。
- proof/explanation 的「命题成立；…=X」结论前缀是**跨 ≥20 个独立样本重复出现的
  表示问题**，命中决策规则 #1（→ 做通用规范化）。但用户已明确「不要全局套用数值
  规范化，证明/解释/有序结构/不等式/表达式必须保持原语义」，因此该项规范化必须
  **有明确边界**（仅针对「命题成立/答案为 X」这类结论前缀，且不触碰自然语言结论、
  不等式、集合、元组），需单独设计 + 单测，作为下一步候选，**不并入本轮**。
- 另需在组合验证阶段回看：英文 `Proof:`/`Explanation:` 标题识别、英文 thinking
  复述的 echo 过滤是否收紧。
