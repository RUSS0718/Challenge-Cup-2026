# 评测方法调研采纳报告与提分行动(2026-08-29)

> 来源:[评测方法学研究](math_agent_evaluation_methods_2026-08-28.md)及缺口核对
> A/B(9 个判分实现源码级核对,证据分级 ✅/⚠️ 完整)。本文回答两个问题:
> **采纳多少**,以及**哪些动作直接服务提分**。

## 一、核心采纳:判分对齐 = 输出卫生(证据强度:源码级)

9 个已核对判分实现(hendrycks 原版、lm-eval hendrycks/minerva、Math-Verify、
OpenCompass、Qwen2.5-Math、DeepSeek-Math、CMATH、MathBench 开放题)分属
三范式 + 一个小类,但存在**全口径安全区**:

> **`\boxed{}` 包裹 + 最简规范形 + 无解释性尾缀**,在全部 9 个口径下均安全。

同时被源码直接证明的失败类(非推测):小数 vs 最简分数不等价(除 hendrycks
的 0.5 特判)、无序集合/区间不归一、单位词表覆盖不全、sympy 解析失败即判错
(自造记法高风险)、**"取最后出现答案"类抽取会被尾缀稀释**、缺句式即
invalid(Minerva 字面 `[invalidanswer]`)。判分器间同一批输出分差 5+ 点、
Math-Verify 自述极端低估 40 点——**判分对齐是真实分数杠杆,不是洁癖**。

### 行动 1(立即立项,发 4 候选):ARH 答案表示对齐

**现状缺口**:本仓 numeric 族 `final_response` = `最终答案：<规范化答案>`,
**无 boxed 形态**;非数值族为重建正文,boxed 依赖模型自觉。官方判分器未知,
但 9 口径证据表明:仅"答案句"喂不饱 boxed 抓取器,仅"boxed"喂不饱位置
抓取器(CMATH/MathBench 式"触发句+数字"假设)。

**ARH 规格**(纯后处理,零新增调用、零 prompt 改动):

```
final_response = "最终答案：<canonical>\n$\\boxed{<canonical>}$"
```

- `<canonical>` = 现有 `normalized_answer`(最简分数优先、无单位、无度符号);
- 双形态并存同时喂饱"答案句+数字"与"last-boxed"两类抓取假设
  (研究文档 §3-10 的原话建议);
- 失败模式审查:CMATH 式"末 2 个数字候选"在双形态下两个候选同值,安全;
  last-boxed 取到 canonical;Minerva 句式抓不到会回退 boxed/末数字;
- 非数值题型(证明/推导)不套用(正文重建已是形态契约);
- 过门标准照旧:双集双轮、invalid 下降、正确率不回退、void 门 10%。

**为什么它是提分候选**:Run #4–#6 的 invalid 池稳定在 17–27,其中
"语义正确但表示不可判"的份额即 ARH 的可回收上限;9 判分器证据表明
boxed+规范形把抓取失败面压到最小。这与 hetero(refine)正交——refine 改
采样与修正,ARH 改最终表示,融合时各自单变量。

### 行动 2(工具):本地双判分器诊断

现有本地判分(hendrycks 口径)之外并行接入 Math-Verify(开源库,只进
本地实验依赖,不进提交环境),逐题记录两口径差集——差集即"表示不一致但
语义正确"的直接量化,为 ARH 与后续卫生候选提供靶子。

### 行动 3(报告口径):正确数附 Wilson 95% 区间

112 题规模下 ±1~3 题在噪声带内(Error Bars 论文 + 本仓官方六轮 9→12 的
震荡自证)。自 Run #7 判读起,官方五数判读附正确数区间,统一"哪些差异
可下结论"的口径。

### 行动 4(纪律确认,零成本)

- invalid ≠ model_error 分治(P1 已按此实现,判分器源码背书该区分);
- **分母纪律**:不效仿 CMATH 把异常回复剔除出分母;
- 报告不引入 LLM judge、不引入 PRM 组件(维持既有排除);
- 不做"判分器猎奇"(反推官方 verify 不对称方向属投机对齐)。

## 二、不采纳清单

| 提案 | 不采纳理由 |
| --- | --- |
| LLM-as-judge 本地判分 | MT-Bench 位置/冗长/自增强偏差;无人工元集,Omni-Judge 与人工仍有 14% 残差 |
| PRM/process 评测组件 | 评测侧基础设施,赛事判 outcome,不进运行时 |
| 判分器定制对齐 | 官方实现未知,投机对齐判错方向反伤分 |
| Math-Verify 作为本地默认报告口径 | 更宽松会美化本地分,只作诊断并行 |
| 强结构化(JSON/XML)输出 | 争议未决(原文 vs dottxt 反驳);双方共识仅"解析器选择改变分数"——支持自由文本+boxed 路线不变 |
