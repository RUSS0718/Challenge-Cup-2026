# 预注册：8k 挑战者 vs legacy 4k+k5 基线（2026-08-24）

> 本文件在实验启动前写定，判据不得事后修改。
> 背景：官方 R4 裁决 B1+4k（8.04%）不敌 legacy 4k+k5（9.82%），B1 出局；
> 8k 家族（baseline8k_k2 / k3_8k）作为挑战者进入同窗口交错比较。

## 臂定义（全部 POLICY_PROMPT + temp 0.6，逐字段钉死于 VARIANTS）

| 臂 | 配置 | 角色 |
| --- | --- | --- |
| `legacy_4k_k5` | 4096 / k5·agree3 / max_calls 5 | 对照（=官方 R2 提交快照） |
| `baseline8k_k2` | 8192 / k2·agree2 / max_calls 2 | 挑战者 P0 |
| `k3_8k` | 8192 / k3·agree2 / max_calls 3 | 挑战者 P1 |

## 设计

- 数据集：`complex_capability_freeze_48.jsonl`（区分度最高），三臂逐题交错 ×2 轮
- workers 3，timeout 240s，retry 1
- 每轮前 API 健康探针（失败等 5 分钟重试，12 次中止）

## 预注册判据（对每个挑战者分别判定）

1. **过门**：双轮均值净增 ≥ +2 且 McNemar p<0.05 → 有资格提交晋升评审
   （修改 SUBMISSION_CONFIG 需用户二次批准，不自动上线）
2. **边界带**：净增 +1 ~ +3 但不显著 → 自动追加第 3 轮后再判；仍不显著 → 记录归档
3. **失败**：净增 ≤ 0 → 8k 家族归档，4k+k5 维持基线
4. **公共集回归**：任一过门挑战者须跑公共 112 ×1 且 correct ≥ 85，否则不晋升

## 成本预估

三臂交错每轮 ≈ 48 × (2.5+3+3.5) min ÷ 3 并发 ≈ 2.9h；×2 轮 ≈ 5.8h。
（legacy 臂 k5 最多 5 调用是时长主项；若首轮实测超预期，允许在轮间把并发
提到 3 不变、仅记录不中止。）
